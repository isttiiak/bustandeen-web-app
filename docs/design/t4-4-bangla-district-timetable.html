Two new page types for the 64 districts, shown for Dhaka district at 375px in dark and light. All times are real (the site's own seo/utils/calc.ts, BD defaults: Karachi method, Hanafi Asr). The QR on the A4 sheet is a real SVG made at build time, so the print needs no network request.

What the rollout would be (one PR each, after your approval)

  • PR 1, data: seo/data/bdDistricts.ts: 64 districts, division, English + Bangla name, HQ coordinates from GeoNames, cross-checked with the BBS list. The 41 existing BD city slugs stay. Each neighbourhood or town page (Paltan, Azimpur, Tungi, ...) gets a "part of X district" link. Districts that are missing get new /prayer-times/{slug} pages.
  • PR 2, monthly pages: 64 x 3 = 192 pages per language (en + bn = 384), plus sitemap entries and a district index grouped by division.
  • PR 3, Ramadan 2027 in Bangla for every district: notice, then the switch to the T4.1 record.
  • PR 4, print: print stylesheet plus the QR. The QR library is a devDependency used only at build time.

Points to confirm before the rollout

  • LookThese mocks use the Bustan Arch tokens with dark and light. The existing SEO pages still use the older slate/emerald colours and dark only. Should the new pages look like this (my suggestion), or match the old SEO pages until those are redesigned?
  • WordingPrayer names follow the app (যুহর, ইশা). Many BD calendars write যোহর and এশা. Keep the app's spelling?
  • AccuracyTimes are pure astronomical. Islamic Foundation tables add a few minutes of caution, so the note says "may differ by a few minutes". Should the pages add a fixed caution margin instead? That would be a fiqh setting, so I would only add it with a source.
  • ColumnsSunrise stays in the monthly table (it marks the end of Fajr). At 375px, 7 columns fit at 13px.
